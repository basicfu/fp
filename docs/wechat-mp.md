# 微信服务号通知接入文档

用户扫一次服务号二维码（没关注的顺便关注），之后业务方就能给他发服务号模板消息：有设备连入、账号在新设备登录这类提醒。

fp 负责的部分：生成二维码、接收服务号的事件推送、维护「这个用户的通知发给哪个微信」、发送模板消息。业务方只需要做三件事：展示二维码、查询状态、按 fp 用户 ID 发通知。

```
客户端                     业务后端                         fp                          微信
  │ 点「开启微信通知」 ──→  WechatSubscribeQR(userID) ──→  生成带参二维码 ─────────→  qrcode/create
  │ ←── 展示二维码 ──────── ImageURL
  │ 用户扫码（没关注的先关注）────────────────────────────────────────────────────→  推送 subscribe / SCAN
  │                                                     ←── /wechat/mp/callback ──  （带场景值）
  │                                                     记下：userID → openid
  │ 轮询状态 ───────────→  WechatSubscription(userID) ──→  Receivable() = true
  │ 关掉二维码，显示「已开启」
  │
  │                       有事发生时：
  │                       Notify().Send(code, userID) ──→  userID → openid ─────────→  message/template/send
```

## 1. 准备

### 公众平台（mp.weixin.qq.com）

1. **认证服务号**。订阅号、未认证的服务号没有带参二维码和模板消息接口。
2. **挂到开放平台账号下**：服务号和网站应用、移动应用挂在同一个开放平台账号下，unionId 才相同。用微信登录过的人自己搜索关注服务号时，fp 靠 unionId 自动替他开启通知（见第 5 节）。
3. **IP 白名单**（设置与开发 → 基本配置）：加上 fp 所有实例的出口 IP，否则取不到调用凭证。开发环境的出口是通知模块的开发代理（`notify.DevProxy`）那台机器。
4. **服务器配置**（设置与开发 → 基本配置 → 服务器配置）：
   - URL：`<public_url>/wechat/mp/callback`，例如 `https://fp.example.com/wechat/mp/callback`。
   - Token：随便生成一串，和 fp 里填的一致。
   - EncodingAESKey：点「随机生成」。
   - 消息加解密方式：选**安全模式**（推荐）。选明文模式的话，fp 里的 EncodingAESKey 留空。
   - **先在 fp 控制台建好供应商（下一步），再点公众平台的「提交」**：提交时微信会立刻调一次这个地址校验 Token。
   - 提交后点「启用」。
5. **模板**（广告与服务 → 模板消息）：从模板库选模板，记下模板 ID 和字段（`thing1`、`time2` …）。新申请的模板要审核。

> **启用服务器配置后，公众平台里设置的「自动回复」「自定义菜单」都不再生效**，这是微信的规则。关注后的欢迎语改在 fp 里配（`followReply`）。

### fp 控制台

**通知中心 → 供应商 → 新建 → 类型选 `wechat_mp`**：

| 配置项 | 说明 |
|---|---|
| AppID / AppSecret | 服务号的开发者 ID 与密码 |
| Token | 和公众平台服务器配置里的一致 |
| EncodingAESKey | 安全模式才填；明文模式留空 |
| 扫码开启通知后的回复 | 用户扫码成功后服务号回给他的文字，留空用默认文案「已开启微信通知，账号的重要动态会在这里提醒你。」 |
| 直接关注时的回复 | 用户自己搜索关注时的欢迎语，留空不回复 |

**一个 fp 部署只能建一个 `wechat_mp` 供应商**：openid 只在本服务号内有意义，两个服务号的 openid 混在一起就分不清了。要换服务号就改这个实例的配置；换了之后，老服务号下的绑定全部失效，用户要重新扫码。

## 2. 配模板

1. **通知中心 → 模板 → 新建**：
   - 渠道选「微信服务号」，模式只有「供应商模板」。
   - code 自己定，比如 `device_connected`。
   - 原文粘贴公众平台里的模板内容（`设备：{{thing1.DATA}}` 这种），点「从原文提取」得到变量 `thing1, time2`。
   - 「点击跳转链接」可选：用户点开消息后打开的网页。
2. **模板详情 → 关联供应商**：选 `wechat_mp` 实例，供应商模板 ID 填公众平台的模板 ID。
3. **测试发送**：收件人填一个**已开启微信通知**的 fp 用户 ID。

字段取值的长度限制由微信规定，超了整条消息会被拒发。fp 会自动截断两类最常见的超长字段：`thing*` 截到 20 个字符、`character_string*` 截到 32 位，末尾补「…」。其他类型（`time`、`phrase`、`amount` …）要业务方自己按微信的格式传。

## 3. 业务后端

```go
n := client.Notify()

// 开启：生成二维码给客户端展示。10 分钟有效，只给第一个扫码的微信用。
qr, err := n.WechatSubscribeQR(ctx, userID)
// qr.ImageURL 直接放进 <img>；想自己画二维码（换颜色、加 logo）就用 qr.Content

// 查询：展示二维码期间客户端每 2 秒问一次，Receivable() 变 true 就关掉二维码
sub, err := n.WechatSubscription(ctx, userID)
// sub.Bound：开启过；sub.Subscribed：绑的微信还关注着服务号；sub.Receivable() = 两者都是

// 关闭：只删绑定。用户在微信里照样关注着服务号，服务端没法替他取关
err = n.DeleteWechatSubscription(ctx, userID)

// 发通知：收件人是 fp 用户 ID
err = n.Send(ctx, "device_connected", userID, map[string]string{
    "thing1": "办公室电脑",
    "time2":  "2026-11-20 10:00",
}, fpsdk.WithIdempotencyKey("conn-"+sessionID))
var fe *fpsdk.Error
if errors.As(err, &fe) && fe.Code == fpsdk.CodeNotifyRecipientUnreachable {
    // 这个人没开微信通知，或者取关了：跳过，不是故障
}
```

这三个 RPC 和 `Send` 一样，要用应用的 AppID / AppSecret 认证，应用必须处于启用状态。用户全局互通，不检查他是否登录过本应用。

**二维码只能给本人看**。谁扫了这张码，这个账号的通知就发给谁，所以只在已登录的客户端里展示，不要放进能分享出去的页面。

## 4. 客户端交互建议

参考 ToDesk 的做法：账号面板里放一行「微信通知」。

- **未开启**：点开弹出二维码，下面写「微信扫码关注，接收安全通知」；同时每 2 秒查一次状态，开启后自动收起，这一行变成「已开启」。二维码过期就提示刷新。
- **已开启**（`Receivable()`）：点开问「是否关闭微信通知」，确认后调 `DeleteWechatSubscription`。
- **已开启但取关了**（`Bound && !Subscribed`）：显示「已失效」，点开重新出二维码。用户在微信里重新关注也会自动恢复，不用重新扫码。
- **`WECHAT_MP_UNAVAILABLE`**：整行隐藏。
- 手机 App 上用户没法扫自己屏幕上的二维码，建议手机端靠系统推送，这一行只显示状态；一定要开的话，给「保存二维码到相册」，让用户在微信里「扫一扫 → 从相册选取」。

## 5. 规则

- **扫码绑定**：用户扫码后，二维码对应账号的通知就发给扫码的这个微信。这个账号原来绑的微信被换下。一个微信可以同时接收几个账号的通知（比如个人账号、工作账号各扫一次）。
- **一码一人**：一张二维码只给第一个扫的微信用。别的微信再扫，服务号回复「这个二维码已被其他微信使用」。同一个微信重复扫照常成功。
- **过期**：二维码 10 分钟后失效，扫了回复「二维码已过期」。
- **自动关联**：用户自己搜索关注服务号（没扫业务方的码）时，fp 按 unionId 找用微信登录过的 fp 账号；这个账号还没开过微信通知的话，就自动替他开上。已经绑了别的微信、或者关掉过通知的不会被改。关掉之后，用户要是重新关注服务号（先取关再关注），算作他又想收通知，会按 unionId 重新开启。
- **取关**：用户取关后，绑定保留但收不到（`Subscribed = false`），发通知得到 `NOTIFY_RECIPIENT_UNREACHABLE`。重新关注后自动恢复。
- **账号注销**：注销生效时，他的绑定一并删除。

## 6. 错误码

| 码 | 什么时候出现 | 怎么处理 |
|---|---|---|
| `WECHAT_MP_UNAVAILABLE` | 通知中心里没有 `wechat_mp` 供应商，或已停用 | 隐藏微信通知入口；去控制台配置 |
| `USER_NOT_FOUND` | 生成二维码时用户 ID 不存在 | 检查用户 ID |
| `WECHAT_UPSTREAM_FAILED` | 生成二维码时微信接口失败：AppSecret 不对、IP 不在白名单里、不是认证服务号 | 看 fp 日志「生成服务号二维码失败」 |
| `NOTIFY_RECIPIENT_UNREACHABLE` | 发通知时：用户没开启微信通知，或已取关 | 跳过 |
| `NOTIFY_RECIPIENT_INVALID` | 发通知时：收件人不是 fp 用户 ID | 传用户 ID |
| `NOTIFY_SEND_FAILED` | 微信拒发：模板 ID 不对、字段超长、用户刚取关而 fp 还没收到取关推送 | 看控制台「发送记录」 |

**服务器配置提交失败（公众平台提示「Token 验证失败」）**：先检查 fp 里是否已经建好并启用了 `wechat_mp` 供应商、Token 是否一致、`public_url` 能否从公网访问。fp 日志搜「服务号回调地址校验失败」。

## 7. 已知限制

- 一个 fp 部署只接一个服务号。
- 事件推送出错时（数据库不可用之类）fp 只记日志、照样回微信 `success`：回错误只会招来重试，而重试解决不了这类问题。这时候用户扫了码却没开启，让他重新扫一次就行。
- 模板消息只有「发出去了」这一个结论，没有送达回执。
- 服务号的昵称头像接口早已停用，fp 拿不到关注者的头像昵称；要头像就让用户用微信登录（网站应用 / 移动应用能拿到）。
